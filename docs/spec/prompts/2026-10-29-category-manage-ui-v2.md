请调整分类管理页面，具体要求如下：

1. **整体层级结构：** 采用 TreeSelect 风格的树形层级组织方式，明确区分一级分类和二级分类。一级分类保持纵向列表，不要将一级分类改为网格布局。

2. **一级分类展开与收起：** 使用 Collapse / Expandable Section 交互。点击一级分类后，在该分类项下方展开或收起对应的二级分类，支持自然的过渡动画。

3. **二级分类的展示形式：** 使用块状分类项（Block-style Items），每个二级分类独立呈现为一个可点击的视觉块，不要把文字镶嵌在胶囊按钮、Chip 或 Tag 中。二级分类采用横向流式布局（Wrap），一行可以排列多个分类块，空间不足时自动换行。

4. **二级分类的点击行为：** 点击单个二级分类块时，弹出该分类对应的 ActionSheet 底部操作面板，展示适用于该分类的操作。不要将二级分类点击行为误做成直接选择或跳转，具体操作应复用项目中已有的业务流程。

5. **一级分类的溢出菜单：** 一级分类右侧的三点图标使用 Overflow Action。点击后通过 ActionSheet 风格的 Modal Bottom Sheet 展示操作项，不再使用 PopupMenu。

6. **层级和操作必须区分：** 点击一级分类主体负责展开/收起；点击一级分类右侧三点负责打开操作面板；点击二级分类块负责打开该二级分类的操作面板。三个交互入口互不冲突。

7. **保持现有业务逻辑：** 修改前检查 HANDOFF.md、相关 Spec 和现有实现，确认分类编辑、停用、删除、账单关联等规则。复用已有数据模型和业务流程，不要擅自修改数据库结构或业务规则。

8. **实现与验证：** 优先沿用现有组件和依赖。不要仅为实现视觉效果就引入新的 UI 组件库。完成后运行相关测试，并汇报修改文件、测试结果及尚未解决的问题。
